# Implementation Plan: Clean Game Session API Contract & Dead Code Elimination

**Branch**: `009-clean-game-contract-dead-code` | **Date**: 2026-10-25 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/009-clean-game-contract-dead-code/spec.md`

## Summary

Clean the Game Session subsystem by eliminating all dead code, transitional compatibility shims, and redundant payload containers, establishing a unified, flat, and strongly-typed API contract between Backend and Frontend:
1. **Unify Session DTOs**: Replace fragmented `GameSessionStartOut` and `GameSessionDetailOut` (and the nested `GameSessionSnapshotOut` wrapper) with a single `GameSessionOut` schema.
2. **Prune Turn Answer Payload**: Remove the redundant `snapshot` field from `GamificationAnswerResultOut`.
3. **Eradicate `tags_filter`**: Completely eliminate `tags_filter` across all schemas, domain entities, use cases, and tests, standardizing solely on `lesson_slug`.
4. **Purge Transitional Shims on Domain Entity**: Remove `@property tags_filter` and `@property snapshot` from `GameSessionEntity` and delete unused standalone helpers from `game_hydration.py`.
5. **Contract-Driven Frontend Update**: Synchronize OpenAPI types (`make generate-api`) and refactor `apps/web/features/game/` to consume the clean schema directly without nested snapshot extraction logic.

## Technical Context

**Language/Version**: Python 3.12 (Backend), TypeScript 5.x (Frontend)  
**Primary Dependencies**: FastAPI, Pydantic v2, Dishka, SQLAlchemy 2.0 / SQLModel, Next.js 14, TanStack Query v5  
**Storage**: PostgreSQL (Normalized columns in `game_sessions` table)  
**Testing**: Pytest (`pytest-asyncio`), `npm run type-check`, `npm run lint`, `make check`  
**Target Platform**: Linux / macOS server (Docker containerized), Web browsers  
**Project Type**: Monorepo Web Application (`apps/api` + `apps/web`)  
**Performance Goals**: Session start / resume response payload reduced by >40%; turn patch response < 5KB  
**Constraints**: Zero dead code; zero transitional shims; 100% type-safe compilation on both BE and FE  
**Scale/Scope**: Clean architecture enforcement across 5 use cases, 1 presentation router, 1 hydration service, and 3 frontend hooks/components

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- [x] **Principle I (Lightweight DDD)**: Concerns remain strictly separated. The domain entity `GameSessionEntity` represents pure business state (no shims). `GameHydrationService` in `application/services` encapsulates presentation DTO mapping. Router functions in `presentation/api/routers/game.py` remain thin 1-3 line delegates.
- [x] **Principle II (Single Source of Truth API Contracts)**: Public API responses strictly define typed Pydantic models. All changes are reflected in OpenAPI, generated into `apps/web/types/api.generated.d.ts` via `make generate-api`, and consumed without manual drift.
- [x] **Principle III (Feature-First Frontend)**: Frontend modifications are localized to `apps/web/features/game/` (`types.ts`, `hooks/use-game-session.ts`, `hooks/use-game-turn.ts`).
- [x] **Principle IV (Test-Driven Verification)**: 100% test pass rate across `apps/api/test/` and pre-commit checks (`make check`).
- [x] **Principle V (Authority & State Separation)**: Server retains exclusive authority over score calculations, lives, and rewards; client handles local UI animation and turn state machine.
